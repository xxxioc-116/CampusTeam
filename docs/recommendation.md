# 推荐算法与实验（#13–#17）

## 数据契约

五维固定顺序：编程开发、数据分析、产品设计、沟通协作、项目管理。
输入能力为 0–100 的有限数字；内部除以 100。整组缺失或单维 null 记为 0，
字符串、布尔值、NaN、无穷、越界、长度错误均拒绝。缺失不是已经测得的零能力，
产品采集端应提示补全画像。skills、experience 为标签数组，去除首尾空格、忽略大小写、去重。
experience 使用已确认的经历类别标签，不能从任意自由文本猜测。

成员逐维最大值为团队能力 C；项目需求为 R；缺口 G=max(R-C,0)。
候选能力 A 实际填补 F=min(G,max(A-C,0))，互补度=sum(F)/sum(G)。
无缺口时互补度为 0，不奖励重复能力。该口径表达“是否有人具备能力”，不表达人数或工作量。
例如 C=[80,40,0,0,0]，R=[100,80,0,0,0]，A=[80,60,0,0,0]，
F=[0,20,0,0,0]，互补度=20/60=1/3。

## 五项评分

| 分项 | 公式 |
|---|---|
| complement | 上述实际缺口填补比例 |
| skill | 命中项目技能标签数 / 项目技能标签数 |
| time | 候选可用分钟与项目协作分钟交集 / 项目协作分钟数 |
| goal | 非空目标类别相同为 1，否则为 0 |
| experience | 命中项目经历标签数 / 项目经历标签数 |

没有需求或缺少信息的分项为 0，不凭空赋满分。时间段按星期 1–7、当日 HH:mm、
左闭右开分钟区间处理；重叠自动去重，跨日需拆分。
默认权重为 0.35/0.25/0.20/0.10/0.10；配置必须包含全部五项、非负且和为 1。
公共输出分项=内部值×100，贡献=分项×权重，总分=贡献之和。
输出不提前舍入；UI 可显示两位小数。按未舍入总分降序、正整数用户 id 升序稳定排序。
top_k=0 返回空列表，超过候选数量返回全部，合法范围 0–1000；候选 id 重复拒绝。
已有本团队成员在评分前排除。正式 API 还应排除停用账户及不符合业务规则的候选人。

推荐理由逐维对应 F，风险包括无能力填补、缺少技能、时间不足或无交集。
自定义权重返回 custom-v1 和实际权重；默认返回 baseline-v1。
未改变 ADR 0001 的默认权重。

## 运行与验证

```powershell
python -m unittest discover -s tests -v
python -m analytics.experiment
```

实验使用 Python 标准随机数、固定种子 20261027，100/500/1000 名合成候选人，
每个能力从 0–100 整数均匀抽样。比较随机抽取、与现有团队余弦相似排序、互补排序。
指标为 Top-5 候选人各自填补缺口比例的均值，不是五人同时加入后的团队效果。
实验只配置能力分项，因此正式加权排序等价于互补排序。每个规模运行七次，报告中位与最大耗时。
合成实验用于回归与复现，不能作为真实满意度或推荐准确率结论。
JSON 中候选 id 和质量指标可复现；机器、负载会改变耗时。
