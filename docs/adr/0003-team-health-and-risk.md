# ADR 0003 团队健康度、共同时间与风险预警

- 状态：Proposed，已本地实现与测试，待小组评审确认
- 日期：2026-10-28
- 关联：#19、#20、#21

## 问题

推荐模块只回答"该邀请谁"，不回答"现有团队是否健康"。课程量规要求健康度
五维公式、权重与风险阈值文档化，且时间重合度、目标一致性和四类风险
（能力重复、关键缺口、共同时间不足、目标不一致）可被独立验收。

## 决策

1. 健康度定义为「团队现状对自身推荐需求的覆盖率」：五个分项与
   `RecommendationRequirement` 字段一一对应（abilities/skills/availability/
   goal/experience），默认权重沿用 ADR 0001 的 0.35/0.25/0.20/0.10/0.10。
   分项缺失（如未配置技能需求）记 0，不凭空赋满分，与推荐口径一致。
2. 时间重合度取全员可用时间交集与需求协作时间的比例：团队协作要求人人
   同时在场。任一成员未填时间则交集必为空，如实计 0，并以
   common_time_insufficient 风险提示"信息可能未填写"，不与"测得为零"混淆。
3. 目标一致性为个人目标与团队目标（大小写不敏感、去首尾空格）一致的成员
   占比；团队目标为空时不评估，记 0。
4. 风险阈值为固定常量并文档化（健康 ≥80、观察 60–79、风险 <60；关键缺口
   ≥30 分；共同时间 <20%；能力重复=≥2 名成员可独立覆盖同一需求维度且其他
   维度仍有缺口）。本期不做 API 可调参数，避免校验面扩大；需要时再发版。
5. 健康度请求时计算，不落库、无历史快照；不需要新数据库模型或迁移。
   读权限与其他团队分析接口一致（成员/队长/业务 ADMIN）。

## 备选与代价

- 成员覆盖率均值口径：更宽松，但与推荐算法"候选人对需求时间的覆盖"不对称，
  且无法表达"共同在场"。
- 需求时间总覆盖（可超 100%）：衡量总投入而非共同时间，不能满足预警语义。
- API 可调阈值：灵活但增加校验与文档负担，课程验收期内口径唯一更重要。
- 健康度不衡量工作量、协作成本或人数需求，也不预测项目成败。

## 验证

纯算法测试覆盖空时间、跨日拆分拒绝、无交集、多交集、目标冲突、四类风险
正反例与文档算例；API 测试覆盖权限矩阵、未配置需求 400、响应结构、权重
生效与风险输出。公式与阈值详见 docs/team-health.md。
