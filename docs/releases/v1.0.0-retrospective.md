- 覆盖率设置全局80%和核心模块60%双门禁。

- 性能回归同时记录耗时和SQL查询数，固定检测N+1。
- 发布证据脚本检查三版说明、必需章节和草案标记，避免“有文件但不可交付”。

## 遇到的问题与根因

| 问题 | 根因 | 处理 | 预防措施 |
|---|---|---|---|
| 早期任务集中在少数大PR | 按模块分工时未同步考虑人均PR指标 | 后续按独立交付物拆分 | 立项时同时规划Issue和PR粒度 |
| Review集中在组长 | 初期只强调代码完成，未设置评审轮值 | 建立交叉Review矩阵 | 每个迭代要求成员评审至少3个不同PR |
| 权限模型出现两套判断 | Django后台权限与业务角色概念混用 | 统一使用 `User.Role.ADMIN` | 在ADR和权限测试矩阵中明确角色口径 |
| 发布证据形成较晚 | Release Notes和贡献说明未进入早期Definition of Done | #28集中补齐并增加自动校验 | Alpha开始即维护Release Notes和贡献索引 |
| benchmark输出路径不安全 | 将CLI参数直接当作文件系统路径 | 固定输出根目录、拒绝目录组件并补测试 | 所有文件写入先做边界和路径归一化审查 |
