# 推荐算法规则与验证表（素材）

## 1 推荐理由生成规则表

| 触发条件 | 输出模板 | 说明 |
|---|---|---|
| F(p,j) > 0 | 可补齐维度 j 共 F(p,j)×100 分 | 逐维对应实际有效补量，不重复能力 |
| skill 贡献 > 0 | 技能命中 hit/total 项，贡献 c 分 | hit 为与项目技能标签的交集数 |
| time 贡献 > 0 | 协作时间覆盖占比，贡献 c 分 | 占比按分钟集合交集计算 |
| goal 贡献 > 0 | 合作目标一致，贡献 c 分 | 目标非空且忽略大小写后相同 |
| experience 贡献 > 0 | 经历类别匹配，贡献 c 分 | 标签交集非空 |
| 全部为 0 | reasons 为空 | 由风险表给出未补齐提示 |

## 2 风险生成规则表

| 触发条件 | 风险提示 | 说明 |
|---|---|---|
| 所有 F(p,j) 均为 0 | 未补齐当前能力缺口 | 候选人与现有团队能力重叠或低于团队 |
| 项目或候选时间信息为空 | 时间信息不足 | 采集端应提示补全 |
| 时间集合交集为空 | 可用时间无交集 | 有能力但无法协作 |
| 候选人技能标签为空 | 技能信息缺失 | 不影响能力分，但影响技能分项 |

## 3 算法复杂度分析表

设 n 为候选人数，m 为团队成员数，d = 5 为维度数，L 为标签数，T 为展开后的分钟集合规模。

| 阶段 | 时间复杂度 | 空间复杂度 | 说明 |
|---|---|---|---|
| 能力向量校验与归一化 | O((n+m)d) | O(1) | 逐维检查有限数字与越界 |
| 团队能力聚合 | O(md) | O(d) | 逐维取成员最大值 |
| 缺口计算 | O(d) | O(d) | 逐维 max(R − C, 0) |
| 候选筛选 | O(n) | O(n) | 评分前排除已有团队成员 |
| 五维评分 | O(n(d + L + T)) | O(1) | 标签与时间为集合交集运算 |
| 稳定排序 | O(n log n) | O(n) | 复合键 (−score, id) |
| Top-K 截取 | O(k) | O(k) | 切片返回 |
| 合计 | O(n(log n + L + T) + md) | O(n) | d 为常数，可化简 |

## 4 推荐对比实验表

固定随机种子 20261027，每个规模重复 7 次，合成候选人能力为 0–100 均匀整数。指标为 Top-5 候选人各自填补缺口比例的均值，不是五人同时加入后的团队效果。数据取自 `docs/recommendation-experiment.json`。

| 候选人数 | 随机 Top-5 平均补量 | 相似排序 | 互补排序 | 中位耗时 ms | 最大耗时 ms |
|---|---|---|---|---|---|
| 100 | 0.32375 | 0.39375 | 0.775 | 0.578 | 0.801 |
| 500 | 0.22750 | 0.03125 | 0.91125 | 2.863 | 4.523 |
| 1000 | 0.46625 | 0.09500 | 0.93000 | 5.838 | 6.468 |

结论：互补排序在三个规模上均高于随机与相似排序；相似排序在 500 与 1000 规模表现最差，印证按现有团队相似度排序无法补齐缺口的取舍。耗时仅反映算法本体，API 与数据库延迟另测；合成实验不能作为真实满意度或推荐准确率结论。
